# 2026-07-18: Always-visible wax shell that cracks underfoot (CakeWaxShell)

Tags: cake-sim, config, juice

## Task
User wanted the cake's crust to read as a **thin wax shell** (reference: the
"Crunchy Butter" ASMR games) that a player CRACKS by walking on it. Converged
over many iterations onto a precise spec:
- an ALWAYS-VISIBLE wax coating over the WHOLE cake (not spawned under the
  player, not a texture, not a following object),
- an ORGANIC web of wax pieces that is SMOOTH at rest and only cracks where the
  foot presses — the pieces DENT, TILT and SPREAD, so the darker cake shows in
  the gaps, then heal,
- the wax DISAPPEARS where the cake is eaten,
- clean edges at the loaf boundary.

## What landed — `CakeWaxShell` (new client module)
ONE MeshPart of organic Voronoi "wax pieces" covering the footprint, built once
via the FixedSize-clone pattern (dynamic EditableMesh scratch → `CreateEditable
MeshAsync {FixedSize}` clone → `CreateMeshPartAsync` → destroy scratch; the
clone still takes `SetPosition`). Each piece:
- owns its BOUNDARY vertices (duplicated, on the exact Voronoi edge so neighbours
  MEET with no gap) + a raised CENTRE vertex (a small `dome`, fan-triangulated),
- rides the deforming surface every frame by re-reading `LocalCakeField.Read
  HeightStuds` (per boundary vertex → neighbours stay coincident on slopes),
- HIDES (verts parked far below) where the centre cell is eaten more than
  `hideDepth` below its layer top,
- under the foot carries a per-piece `dent` 0..1 (ramps `fracture.riseRate`,
  heals `fracture.healRate`) that DENTS it down (`-sinkDepth·dent`), TILTS it
  (one edge up along a per-piece axis) and SPREADS it toward its centroid
  (`gap·dent`) — so cracks open ONLY underfoot and the cake body shows in them.
- is clipped to the loaf's rounded-rect outline (inset `edgeInset`) so the web
  stops cleanly inside the edge — no jagged overhang.
- colour = a BRIGHT vivid GLAZE (HSV sat/val boost of the layer's top colour,
  not a pale wax) of the current OUTERMOST REMAINING layer (`maxH` band, not
  the foot), so standing in a crater on an exposed lower layer does NOT re-tint
  the un-eaten areas — it only changes when a whole layer is eaten (one/mesh).

Slabs now render the layer BODY (CakeRenderer `paintBandImage`/`updateCellPixels`
— the crust look is the wax shell on top, so the body shows through the gaps).

## Key fixes / gotchas
- **Build race (the "run-immediately breaks it" bug).** `ensureBuilt` YIELDS
  (async mesh creation). Called inline from RenderStepped, a second Step during
  the yield re-entered it and appended pieces to a SECOND scratch → the piece
  list mixed vids from two meshes, so only the pieces you spawned on worked.
  Fix (adversarial-review hardened): the build runs in a `task.spawn` (so the
  yield never stalls the rest of the render step) with a `building` guard set
  BEFORE the spawn to block re-entry, and a `pcall` so a throw can't leave
  `building` stuck true; every failure path sets `buildFailed`. Verified with
  spawn-and-immediately-run playtests.
- **Eaten test must use a STABLE reference.** First version compared each
  piece's height to `surfaceBand(hC)` — the band CONTAINING it — which re-bases
  at every layer boundary: wax blinked back on in the top `hideDepth` of each
  layer as you dug, and a fully-eaten crater FLOOR showed wax. Fix: hide against
  the OUTERMOST REMAINING height (`lastMaxH - hideDepth`, 1-frame lag) — a
  crater is below it → hidden; the colour uses the same `maxH` band.
- **Idle perf.** ~234 pieces × ~6 verts re-written every frame is ~84k
  `SetPosition`/s (each dirties the mesh) even standing still. Fix: a per-piece
  dirty-skip — a resting piece whose height + hidden state are unchanged is
  skipped (matches CakeRenderer's `>0.004` write guard).
- **MeshPart cull bounds come from CREATION geometry** — the pieces are built
  spread over the cake (birth Y at mid-height) so the bbox covers the play area;
  RenderFidelity.Precise renders the live SetPosition edits.
- **Rojo duplicates a freshly-created ModuleScript** in Studio (two identical
  instances) → two module states, orphan meshes, budget contention. Kill the
  stale twin in Edit mode when testing a NEW module (bootstrap is name-keyed).
- **Wax colour is one per mesh.** As you eat down uniformly the top layer
  changes and the wax re-tints; multi-layer crater edges get the foot-layer
  colour (a known limitation of one-colour geometry).
- `WritePixelsBuffer` / EditableImage were NOT used (this is geometry, not
  texture) — the earlier texture-reveal and follow-cluster attempts were removed.

## Config (`render.wax`)
step, plateStuds, lift, dome, lighten, hideDepth, edgeInset, gloss, crackRadius,
gap, tilt. Reuses `render.fracture` (riseRate/healRate/sinkDepth) for the dent.

## Studio verification (live)
Boot clean, zero errors: `wax web built — ~234 Voronoi pieces (1 mesh)`. Rest =
smooth pink coating; stepping opens cracks (pieces tilt+spread, cake shows) only
underfoot and they heal; eating a crater removes the wax there (raw layer shown);
edges clip cleanly to the loaf outline; two run-immediately-from-spawn tests all
pieces live, no errors.

## Abandoned approaches (why the churn)
Texture colour-reveal (looked like a smudge) → geometric buckle+grooves ("scary
black") → rigid plate cluster / wax-shard patches that FOLLOWED the foot ("parts
levitate / follow you") → integrated texture cracks ("still a texture") →
stamped 3D shard patches ("appear under the player, not a field") → the
full-surface wax web here. Lesson: the requirement was a FIELD that cracks in
place, not an effect spawned/anchored to the player.
